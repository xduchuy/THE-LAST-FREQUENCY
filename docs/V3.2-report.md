## C. Fixes and clock policy

- E2E alone pins `ubuntu-24.04`; validation remains independent. Keep browser/dependency installation, actual `npm run test:e2e`, failure screenshots/traces/HTML report and evidence upload. `CHROMIUM_PATH` override remains first; otherwise managed Chromium is preferred, with a system binary only when it exists.
- New `mission-clock.js`: monotonic `performance.now()` authority, fixed 50 ms resource simulation and bounded visual delta. Every active interval is credited, including fractional remainders and the instant Pause opens. Pause/overlay/hidden intervals and offline/reload time are excluded; resume starts a fresh anchor.
- Recording requires valid reception, same station and held input at both observed endpoints. A gap over **2 seconds** has no recording evidence: charge the full known idle-power interval (including battery, cooling, storms, cooldown and deadline), decay recording and show HUD feedback. A genuinely held pointer/key retains ownership, and capture can only resume from new valid observations after the gap. Foreground play keeps counting; releasing a hold, blur, overlays and terminal states still clear input, and OS Space repeats cannot create a new hold. Player Pause and hidden-tab policy remain separate. Catch-up stops at terminal and is bounded by one maximum mission (21,601 steps), not arbitrary elapsed host time. Exploratory automatic stall modals caused queued touches to hit modal buttons on slow rendering. The final foreground policy removes that unsolicited modal and retains full time/resource charges, bounded catch-up and a real blocked-thread regression above 2 s.
- `mission.js` checks terminal boundaries before recovery/actions and immediately after code penalties, rejects malformed codes and restores exhausted saves as losses. Penalties stop at the deadline boundary. Final loss processing closes the Journal, releases input, powers down, synchronizes audio and force-flushes the terminal save alongside one report.
- `evaluateReception()` returns eligibility, reason, target and duration for both gameplay and HUD; `reception.js` supplies corresponding Vietnamese text. No separate HUD-ready rule remains.
- Drag pointer, capture pointer and keyboard hold have separate ownership. Unrelated up/cancel events do not release a gesture; blur, overlays, resize and game over force cleanup.
- Low Quality now bounds the radio drawing buffer at 360,000 pixels on large canvases while retaining CSS framing/raycast coordinates. The quality toggle now updates shadows too (previously it only changed DPR). High Quality retains its original DPR policy.
- UI telemetry is limited to 100 ms intervals, unchanged text/HTML is retained, waveform/scene remain in the render loop. One-shot oscillator/gain/filter nodes disconnect on completion; thunder and station scheduling guard inactive states. No per-frame texture creation was introduced.
- Context loss now releases input and exposes the mobile HUD fallback; restoration hides it and keeps the existing renderer/mission.
- Version/title, README, changelog and this report document the new policy; storage key/schema remain compatible with V3.1. Existing migration/archive tests remain enabled.
